# FRONTEND DATA FLOW

Inertia 3 is the transport. Reach for the native feature first; `lib/http` is the exception.

Read JSON whose answer a component shows (a preview, a stock count, a search box) with `useJsonQuery(key, load, { delay })` from `@/hooks/use-json-query`: it asks again when `key` changes (`null` asks nothing), keeps each answer with the key it was asked for, ignores a late or canceled one, aborts on unmount and returns `idle`, `loading`, `loaded` or `failed`; `delay` debounces a search box and `retry` asks again. Any other debounce (a callback, a reload, a hover delay) is `useDebounce` from `@/hooks/use-debounce`, which also clears its timer on unmount; ESLint fails a timer that is cleared and armed again in the same function, and the `use-debounce` package. Example: `Components/features/products/components/product-search.tsx`. A request that an event or a one-time mount action sends lives in a function outside the effect (a `useEffectEvent`). ESLint (`no-restricted-syntax`) fails `http.get`, `http.query` or `http.post` inside `useEffect`.

Layouts are Inertia layouts: `resolvePage` assigns `Component.layout` (`TenantLayout` plus `AppShell` or `AdminShell`), so
the sidebar stays mounted between visits. A new page under `Product`, `Order`, `Dashboard`,
`Warehouse`, `Notifications` or `Profile` gets the app shell; `Admin/` and `Landlord/` get the admin shell.
The tests in `inertia-app.test.tsx` fail when a page uses the wrong one.

Server errors reach Inertia visits as the `Error` page (`Inertia::handleExceptionsUsing`); full page loads keep the Blade views.
A successful visit that changes data empties the prefetch cache (`lib/prefetch-invalidation`), and partial reloads keep
validation errors on screen (`lib/visit-defaults`).

- A success is always the server's flash; the client never adds `toast({ variant: "success" })`. Show a running visit with `useVisit` (`track(options)`, `processing`).
- Window and document events: `useWindowEvent` and `useDocumentEvent` from `@/hooks`, or `listenToWindow` and `listenToDocument` from `@/lib/dom-events`, which return the function that removes the listener. Media queries in a component are `useIsMobile`, `useIsDesktop` or `useIsWide`; `useMediaQuery` is only what those hooks are built on.

# TESTS

- Every test runs and passes, or is deleted. ESLint (`no-restricted-syntax`, `focusedTestRules` in `eslint.config.js`) fails a focused, skipped, todo or expected-to-fail test: `.only`, `.skip`, `.todo`, `.skipIf`, `.runIf` and `.fails` on `it`, `test`, `describe` and `bench`, and `fit`, `xit`, `xtest`, `fdescribe` and `xdescribe`. The ratchet row `vitest-skip` in `scripts/ci-ratchets.sh` stays at 0.
- A test asserts the behavior it names: the role, name or text a user meets. No snapshot test; the same rule group fails `toMatchSnapshot`, `toMatchInlineSnapshot`, `toMatchFileSnapshot` and `toThrowErrorMatchingSnapshot`.
- A page test mocks its layout with the shared stand-ins: `vi.mock("@/Layouts/form-page", () => import("@/__mocks__/form-page"))`, likewise `authenticated-layout`, `admin/admin-index-layout` and `admin/admin-form-page`.
- A component that renders recharts or `ChartContainer` is tested with `rechartsFakes` and `chartUiFakes` from `@/__mocks__/chart-fakes`; a child the test does not look inside is `componentStub(name)` from `@/__mocks__/component-stub`, which keeps the props it received.

In vitest every lucide icon renders as an empty `<svg data-lucide="Name" aria-hidden="true">` with the props it was given
(`__mocks__/lucide-icon.ts`, wired in `vitest.setup.ts` and `vite.config.ts`). The icon adds no text, so match names and
copy with exact strings, and check which icon shows with `[data-lucide="Name"]`, where `Name` is the canonical export
without the `Icon` suffix (`Trash2`, `LoaderCircle`).

`@inertiajs/react` has one fake for every test file: `__mocks__/inertia/react.tsx`, wired in `vitest.setup.ts` and reset before each test. A test never writes `vi.mock("@inertiajs/react")` (ESLint fails it). It reads `router` from `@inertiajs/react` (every method is a `vi.fn()`; give one behavior with `vi.mocked(router.post).mockImplementation(...)` in `beforeEach` or in the test, because the reset wipes it), sets the page with `setPage` or `setPageProps` and the answers of `useHttp` with `setHttp({ post: (url, data) => ... })`, all from `@/__mocks__/inertia/react`. A page change after mount goes inside `act`. `Link` is an anchor with `data-inertia`, `data-method`, `data-payload`, `data-prefetch` and `data-preserve-scroll`; `Head` renders the `<title>`; `usePoll` and `WhenVisible` are spies around a working stand-in; `http` and the types stay real.

The fake `useForm` is `createUseForm(router)` from `@/__mocks__/inertia/use-form`; ESLint (`no-restricted-syntax`) fails any other `useForm:` fake. It keeps its data, errors and
dirty state like the real hook and sends each submit through the mocked `router`, so a test asserts
`router.post(url, data, options)` and calls `options.onError({ field: "..." })` to show a server error at its field.
The fake `useHttp` is `createUseHttp` from `@/__mocks__/inertia/use-http`, fed by `setHttp`:
the function returns the JSON body, and a rejection with `response.status` 422 shows its `errors` per field. Its
`withPrecognition(method, url)` gives `validate`, `validating`, `valid` and `invalid`, answered by the same `setHttp`
function at once (no validation timeout). A test of the real package (server render, hydration, a precognitive request
through a stubbed `fetch`) starts with `vi.unmock("@inertiajs/react")` and gets its page from the real `App`.

A fake of a hook result, a DOM event or a browser object is `mockOf<T>({ ... })` from `@/__mocks__/mock-of`: it takes a deep partial of `T`, so a wrong key or value type fails tsc. A mocked function is `vi.mocked(fn, { partial: true })` or a typed `vi.fn<Fn>()`, a global is `vi.stubGlobal(name, value)` (also `route`). ESLint (`@typescript-eslint/consistent-type-assertions`, `never`) fails every type assertion; only `as const` stays. Narrow with a type guard (`@/lib/type-guards`), `satisfies`, `instanceof`, `requireInstance`/`requirePresent`, or a parser (`parseJson` from `@/lib/parse-json`); keys of a record the app wrote itself come from `keysOf`, `entriesOf` and `mapKeys` in `@/lib/typed-object`. JSON from `lib/http` is `unknown`: pass the response through `acceptResponse(guard)` from `@/lib/http-response` (shared guards in `@/lib/response-guards`), and `useLocalStorage(key, initial, guard)` reads storage through a guard. A URL the client already holds or a reload goes through `navigateToUrl` / `reloadPage` from `@/lib/full-page-navigation`, the only file that writes `window.location` (ESLint `navigation/no-location-write`).

CI runs `scripts/ci-frontend-tests.sh`: `npx vitest run --coverage` (v8, lcov in `build/frontend-coverage`) and an upload to the coverage service under the flag `frontend`. That number informs and never fails a pull request; a failed upload does not fail the step.

No `console` calls (ESLint `no-console`): use `createDebugLogger` from `@/lib/debug` for diagnostics and Sentry's client for failures.

# INDEXED ACCESS

`tsconfig.json` sets `noUncheckedIndexedAccess`, `noImplicitOverride`, `noImplicitReturns`, `noFallthroughCasesInSwitch`, `noUnusedLocals`, `noUnusedParameters` and `noUncheckedSideEffectImports`, and sets `allowJs`, `allowUnreachableCode` and `allowUnusedLabels` to `false`: every source file is TypeScript, an `import "./x"` for its side effect names a file that exists, and code after a `return` or `throw` is an error. With the first flag, `items[0]`, `record[key]` and a regex group are `T | undefined`. Narrow them (`items.at(-1)`, `match[1] ?? ""`, `const [first] = items; if (!first) return`, a `Record<Union, T>` for a closed key set), never `!`. `requireDefined` from `@/lib/require-defined` is for an item whose existence the caller has just established (a test fixture, `mock.calls[0]`); it throws a clear error instead of rendering around a bug; `requirePresent` from `@/lib/require-present` is the same for a `null` result too (a DOM query, a ref after mount). Do not silence these errors with a TypeScript suppression comment.

# BROWSER APIS AND LIST FILTERS

Each browser API has one door, because blocked storage, a missing `matchMedia` and a login redirect must behave the same everywhere. Storage: `readStorage`, `writeStorage`, `removeStorage`, `clearStorage` from `@/lib/browser-storage` (a read gives `null` and a write `false` when the browser blocks it; parse and validate the string yourself). Media queries: `matchesMedia` and `subscribeToMedia` from `@/lib/media-query`, or `useMediaQuery` in a component. A file the user downloads: `fetchDownload` from `@/lib/fetch-download`, and bytes are handed to the browser as a file with `downloadBlob` from the same module (ESLint `downloads/no-download-link` fails a hand-built `<a download>`); JSON goes through `lib/http` (see the table above). ESLint (`no-restricted-globals`, `no-restricted-properties`) fails `localStorage`, `sessionStorage`, `matchMedia`, `fetch` and `XMLHttpRequest`, also as `window.` and `globalThis.`, outside those files, and `Intl.NumberFormat` outside `lib/number-format`. Tests, stories and mocks are exempt.

A list that filters, searches or sorts through the URL uses `useResourceQuery` from `@/hooks/use-resource-query`: it keeps the search box in step with the page, debounces it and is the only caller of `router.get` (ESLint fails it in `Components`, `Features`, `Layouts`, `Pages` and `Providers`; another visit is `router.visit`). A table page calls `useResourceIndex` (`Components/admin/hooks/use-resource-index.ts`, adds the table sort), a card page calls `useResourceFilters` (`hooks/use-resource-filters.ts`, adds the category and the default sort). Example: `Components/features/products/product-filters.tsx`.

# BACKEND ENUMS AND BROADCAST EVENTS

A backend string enum the frontend needs gets `#[TypeScript]`; `php artisan typescript:transform` writes it to `types/generated.ts` as an `enum` and the frontend imports it (`OrderStatus.PAID`, `Exclude<OrderStatus, OrderStatus.CANCELED>` for a subset). A union of the same values, a bare string compared with a value, and a `string` where the Data holds the enum are all copies that drift when a case is added. ESLint (`no-restricted-syntax`, `generatedEnumUnionRules` in `eslint.config.js`) fails a union of the values of the enums it lists; add an enum to that list when you convert one. The frontend writes no `enum` by hand: an enum only comes from the backend through `types/generated.ts`, and a set of values the frontend owns is an `as const` object with a union type of its values (`Components/features/order/utils/order-filters.ts`). ESLint (`no-restricted-syntax`, `sourceShapeRules` in `eslint.config.js`) fails a hand-written `enum`. A Data class that carries a list of such values says so with `#[LiteralTypeScriptType('XData[]')]`, never an inline union.

A broadcast event's payload is a `*Data` class with `#[TypeScript]` (`StockLevelData`), and `broadcastWith()` returns its `toArray()`; snake_case keys on the wire are `#[MapName(SnakeCaseMapper::class)]` on the class. A listener is `useEchoEvents<Events>(channel, handlers, options)` from `@/hooks/use-echo-events`: `Events` maps the event name without its leading dot to the payload type, `handlers` has one function per name (`"stock.*"` for a family that differs in a suffix), and the hook reads the latest handlers at event time. Never cast `ctx.payload` and never strip the dot yourself. Example: `Components/features/warehouses/hooks/use-stock-level-echo.tsx`.

# FILE NAMES

Files and folders are kebab-case: `use-order-filters.ts`, `order-line/order-line.tsx`, `order-summary.totals.test.tsx`. A component's
export keeps its PascalCase name; only the file is kebab. There are no `index.ts` barrels: import the module that defines the name
(`@/Components/ui/button/button`). The fixed folders are `Components`, `Features`, `Layouts`, `Pages` and `Providers`, and `__mocks__` mirrors
module paths. A page under `Pages` keeps the PascalCase name its controller renders (`Inertia::render('Order/Index')`), so renaming one is a
change in PHP too; the `components`, `parts` and `stories` folders inside `Pages` are kebab-case. ESLint `names/kebab-case` (`eslint.config.js`)
fails any other name and any `index.ts`; `types/index.d.ts` is the one `index` file, the global type augmentation.

# EFFECTS AND REFS

A ref that holds the latest prop or callback is written in `useEffect(() => { ref.current = value; })`, not during render (`react-hooks/refs`). Example: `Components/features/notifications/hooks/use-on-unread-count-increase.ts`. Use `useLayoutEffect` only when the ref is read during render, so it must be current before the paint (`Components/ui/data-table/data-table.tsx`).

State that mirrors a prop is adjusted during render (`if (synced !== prop) { setSynced(prop); setState(prop); }`), not in an effect that calls `setState` (`react-hooks/set-state-in-effect`). Example: `hooks/use-resource-filters.ts`.

A component takes `ref` as a prop like any other (React 19): `const X = ({ ref, ...props }: XProps) => ...`, never `forwardRef`. ESLint (`no-restricted-syntax`, `sourceShapeRules`) fails `forwardRef` and `React.forwardRef`. Example: `Components/ui/input/input.tsx`.

# FILE SIZE

A file in `resources/js` has at most 400 lines (ESLint `max-lines`). Split a long component into presentational children that get their data as props (state and effects stay in the parent), and a long module into the helpers, types and constants it holds, each in its own kebab-case file named after what it does. A test file counts too: split it by the behavior it covers into `<file>.<topic>.test.tsx` next to it, each with only the mocks it needs. Stories, mocks and the vendored `Components/ui/sidebar/sidebar.tsx` are exempt. There is no list of files that may stay long: a hook whose parts share state is split into hooks that each own one piece and take the shared refs as arguments (`Components/features/products/hooks/use-product-import.ts`).

ESLint runs typescript-eslint `recommendedTypeChecked` and `stylisticTypeChecked` (type-aware, through `projectService`) plus `no-unnecessary-condition`, `switch-exhaustiveness-check` and `no-non-null-assertion`, and the React Compiler rules of `eslint-plugin-react-hooks`, all at `error`. A rule the whole tree is at 0 for is named as `error` in `eslint.config.js`, one by one, so a preset that changes cannot drop it: `settledCoreRules` for every linted file (the Node scripts too), `settledTypedRules` for every TypeScript file and `settledReactRules` for components, next to `one-var` (`never`), `@typescript-eslint/no-misused-spread`, `react/jsx-curly-brace-presence` (`never`), `react/jsx-max-depth` (8) and the stricter `jsx-a11y` rules for roles. A new rule joins its group once the tree is at 0 for it. Trust the declared type: no `?.`, `??` or `if` on a value the type says is never nullish (fix the type where it lies, never a cast to hide it), no floating promise (`void` it or `await` it), no `async` function without an `await` (return `Promise.resolve(x)`), no `any`, and a mock is typed (`vi.hoisted<T>(...)`, `vi.fn<Fn>()`, `mockOf<T>()`). An object shape is a `type`, not an `interface`; only the module augmentations in `types/*.d.ts` are interfaces. An effect that must run on a trigger but read the latest props or state calls a `useEffectEvent` function (`hooks/use-poller.ts`), never an `exhaustive-deps` disable comment. No lint-suppression comment is left in the tree and none is added (the suppression row of `scripts/ci-ratchets.sh` is 0); ESLint reports an unused one. A look override on a ui component is a variant of that component, never a disable comment.

# COMMENTS AND TESTS OF LOGIC

No comments by default. Keep one only when a future agent would act differently because of it: a non-obvious constraint, invariant, ordering or locking rule, external quirk, or security or privacy reason. Never restate the code. The ratchet row `comments` (`scripts/ci-ratchets.sh`) counts comment lines in `resources/js` and fails a pull request that adds one without `[ratchet: comments] <reason>` in a commit that touches the file.

A hook (`use-*.ts`) and every file under a `hooks`, `utils` or `lib` folder has a test next to it, `<file>.test.ts(x)` or `<file>.<topic>.test.ts(x)`. `bash scripts/debt-dashboard.sh --offline` counts the ones without (row `frontend-logic-without-test`) and fails the PHP checks step above the cap in `scripts/debt-caps.json`. A component, a `.tsx` file outside `Pages` and `Components/ui` that is no hook, story or mock, has a `<file>.test.tsx` or `<file>.<topic>.test.tsx` next to it too; the row `frontend-components-without-test` counts the ones without against its own cap. A cap only goes down: new code comes with its test, and the ratchet row `dashboard-cap-headroom` fails a pull request that raises one.

# FUNCTIONS, HOOKS AND IMPORTS

A function is a const arrow: `const formatX = (value: string): string => ...` (ESLint `func-style`). One that needs `this` (a constructor fake in a test) or `yield` is a function expression (`const X = function (this: T) { ... }`); an overload signature keeps its declaration, which the rule allows. A hook is a named export (`export const useCan = ...`, `import { useCan } from "@/hooks/use-can"`), and a `vi.mock` factory names it (`{ useCan: () => true }`); ESLint (`no-restricted-exports`) fails a default export in `hooks/` and in any `use-*.ts(x)` file. Pages, lazily loaded components and story metas keep their default export. Import from `react` by name (`import { useState, type ReactNode } from "react"`): the JSX runtime needs no `React` in scope, and ESLint fails `import React`, `import * as React` and `React.X`.
